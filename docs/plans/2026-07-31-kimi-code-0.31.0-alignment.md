# Kimi Code Desktop 对齐 Kimi Code 0.31.0 实施计划（V4）

## 0. 文档状态与使用方式

| 项目 | 内容 |
| --- | --- |
| 状态 | 已完成协议、架构与规范复核；本版可作为实施基线 |
| 代码仓库 | `source/kimi-code-desktop` |
| 文档位置 | 外层项目根目录，按用户要求作为工作看板保留 |
| 版本管理 | 外层根目录不是 Git 仓库。实施前须将本版同步到 `source/kimi-code-desktop/docs/plans/`，并指定仓库内副本为代码变更的可审查基线，避免两份计划漂移 |
| 当前 Desktop | `v1.0.0` |
| 当前本机 CLI | `0.30.0` |
| 首个验收目标 | `kimi 0.31.0`；版本号只作测试/诊断提示，功能门控以运行时 capability 为准 |

本计划的目标是把 Desktop 变成 Kimi Code 0.31.0 的可靠 ACP 客户端，而不是把 TUI 的所有命令逐项复刻成桌面按钮。桌面端只有在能力被稳定声明、端到端验收、并可说明限制时，才可标记为“已支持”。

## 1. 已确认的协议与现状

| 事实 | Desktop 约束与缺口 |
| --- | --- |
| `initialize` 返回 `agentInfo`、`agentCapabilities`、`authMethods` | 归一化为运行时能力状态；不得与会话配置混用，也不得持久化原始认证数据 |
| `session/new` 返回 `sessionId` 与 `configOptions[]` | 归一化为按 `sessionId` 隔离的会话配置状态；当前本地只取 `sessionId`，丢弃其余结果 |
| `session/update` 可发送 `config_option_update` 与 `available_commands_update` | 必须贯通 translator、live、replay、store、UI；当前仅有动态命令 update 的专门翻译 |
| `session/set_config_option` 是 model/thinking/mode 的统一入口；`session/set_mode` 是兼容路径 | 新会话配置优先使用实际声明的 option；现有 `set_mode` 保持为兼容回退，不可回归 Plan/permission |
| `/secondary_model` 修改全局 `[secondary_model]`，且需要 `secondary-model` 实验功能 | 不承诺为 ACP 普通会话 picker；单列为实验性全局配置能力 |
| Task 与 Cron 是 Agent 内置工具，不是 ACP 客户端 RPC | 首期只能观察、回放、展示和在收到后续事件时通知；没有直接 `TaskStop` / `CronCreate` / `CronDelete` 按钮 |
| Plugin 改动要 reload 或新会话才稳定生效 | 插件状态必须区分磁盘、配置与当前会话；扫描目录不等于运行时已加载 |
| Agent 文件有显式 > 项目 > extra > 用户 > Plugin > 内置的优先级；项目 `override: true` 可替换系统提示词/工具限制 | 发现页必须展示来源优先级与 override 信任风险；未知或不可归因时只能显示 unknown，不能假称当前会话已使用 |

## 2. 不可违反的边界

1. **ACP-only：** 只编排用户安装的 `kimi acp`，不得恢复 Python sidecar 或其它 legacy runtime fallback。
2. **Capability 优先：** 每个控件以 `agentCapabilities`、当前会话 `configOptions`、`available_commands_update` 和实际事件形状门控；CLI 版本只用于兼容提示与测试矩阵。
3. **无敏感信息持久化：** 不落盘原始 initialize 响应、认证信息、Provider 密钥或 plugin system prompt 正文；仅保存脱敏后的状态/摘要。
4. **完整事件链：** 新 update 必须覆盖 `src/hooks/wireTypes.ts / src-tauri/src/wire_events.rs → src-tauri/src/acp_translate.rs → live dispatch → session_store replay → state/store → semantic UI → generic fallback`。
5. **单活跃流：** `useSessionStream` 未完成独立架构迁移前只维护一个 active-session stream；不能提前承诺切换会话后的后台保活或跨会话通知。
6. **不伪造上游能力：** 直接 Task/Cron 控制、插件安装/启停、Provider 网络探测、fork-at-turn 等，未获稳定、可审计的控制契约时只显示限制或 CLI 指引。
7. **保护并行工作区：** 每项开始前运行 `git status --short --branch`。若目标文件已被改动或 owner 不明确，停止编辑并先约定接口；不得覆盖无关更改。
8. **热点串行：** `acp.rs`、`commands.rs`、`tauri-api.ts`、`useSessionStream.ts`、`acp_translate.rs`、`session_store.rs` 在同一时间只有一个 owner。

## 3. 路线图与 Go / No-Go 门槛

~~~text
G0 兼容性证据、能力模型、IPC 所有权
  ├─ G1a 会话级 model / thinking / mode
  ├─ G1b secondary model 与实验开关
  ├─ G2a 插件与自定义 Agent 可观察性
  ├─ G2b Provider 安全配置体验
  ├─ G3 后台任务与 Cron 可观察性
  ├─ G4 独立的低风险会话增强
  └─ G5 多活跃会话与上游依赖能力
~~~

每个 Gate 可独立提交、验收或暂停。上游契约阻塞一个 Gate 时，其他无依赖 Gate 可继续；不得用跨 Gate 重构或假 UI 绕过阻塞。

### G0 — 兼容性证据、能力模型与 IPC 所有权（P0）

**目标：** 先精确知道各 CLI 版本和会话实际提供的能力，再实现新的桌面控件。

**实施：**

1. 建立脱敏 ACP fixture，至少覆盖 `0.30.x` 与 `0.31.0` 的 `initialize`、`session/new`、恢复/重连、`config_option_update`、`available_commands_update`、TaskOutput 终态通知和未知 update。
2. 建立两个不混用的状态模型：

   - `AgentRuntimeCapabilities`：来自 `initialize`，仅包含版本、能力与认证方法摘要；
   - `SessionConfigState`：仅来自会话创建/加载的实际响应和后续 `config_option_update`，按 `sessionId` 隔离。

3. 规定配置失效规则：会话关闭、重建或切换时不复用旧会话 option；恢复路径未返回配置且尚未收到 update 时显示 unknown。
4. 在实现前以真实 0.31 ACP trace 决定 `session/set_config_option` 由哪个现有会话所有者发送：长驻 `AcpDesktopClient` 或每会话 wire worker。不得创建第二条竞争性 RPC 通道。
5. 任何新增 Tauri 调用遵守完整链路：

~~~text
Rust implementation + test
  → commands.rs IPC wrapper
  → lib.rs generate_handler registration
  → tauri-api.ts wrapper/type
  → frontend caller + adjacent test
~~~

6. 版本号仅提供“已验证版本/建议升级”信息；缺 capability 或 option 时由能力状态禁用控件。
7. 用真实 Tauri/WebView2 验收记录 0.31.0 的归档会话、图片/资源链接、动态命令、配置 update 和 TaskOutput 后续事件。
8. 运行 ACP-only 门禁并人工分类注释/测试命中：

~~~powershell
rg -n "kimi-sidecar|KIMI_CLI_BIN|call_desktop_api|WireProcessManager" src-tauri src package.json scripts
if (Test-Path sidecar-adapter) { throw "sidecar-adapter must not exist" }
~~~

**主要落点：**

- `source/kimi-code-desktop/src-tauri/src/acp.rs`
- `source/kimi-code-desktop/src-tauri/src/acp_desktop.rs`
- `source/kimi-code-desktop/src-tauri/src/acp_translate.rs`
- `source/kimi-code-desktop/src-tauri/src/wire_events.rs`
- `source/kimi-code-desktop/src-tauri/src/session_store.rs`
- `source/kimi-code-desktop/src-tauri/src/commands.rs` 与 `source/kimi-code-desktop/src-tauri/src/lib.rs`
- `source/kimi-code-desktop/src/hooks/wireTypes.ts`
- `source/kimi-code-desktop/src/hooks/useSessionStream.ts`
- `source/kimi-code-desktop/src/lib/tauri-api.ts`

**Go / No-Go：**

- **Go：** 0.30/0.31 fixtures 都可解析；缺 capability/option 时 UI 安全降级；真实 `npm run smoke:acp` 的环境结果与代码结果分开记录。
- **No-Go：** 把 `configOptions` 继续放进 initialize 状态、只修 live 或 replay 一侧、需要持久化敏感认证数据、或新增并行 RPC 所有者。

### G1a — 会话级 model / thinking / mode（P0）

**目标：** 让 composer、状态栏和 Settings 显示/修改的值与 ACP 当前会话实际生效值一致。

**实施：**

1. 仅为 `SessionConfigState` 已声明的 model、thinking、mode 渲染选择器。
2. 修改时调用 `session/set_config_option`；旧运行时或明确不支持 option 的会话按实际 capability 回退到 `session/set_mode`，或显示不可用原因。
3. `config.toml` 继续保存全局默认值与 Provider 定义，不能覆盖已经由会话声明的实际值。
4. `config_option_update` 必须同时更新 live、replay、store、composer、状态栏和 Settings；保留 loading、error、unknown fallback。
5. 先写失败 fixture/单元测试，再实现 Rust、IPC、hook 和 UI 链路。

**验收：**

- 同一全局默认值下，顺序切换的两个会话可各自显示实际 option；G5 前不要求并发渲染。
- 前端不能发送未声明的 config id 或候选值。
- 既有 Plan/permission 的 `session/set_mode` 语义和测试不回归。

### G1b — secondary model 与实验开关（P1，独立于 G1a）

**目标：** 提供与官方 `/secondary_model` 一致、不会误报为普通会话模型切换的桌面入口。

**实施：**

1. 先验证 `secondary-model` 实验开关的配置或环境来源、`[secondary_model]` 和已有全局配置写入的精确语义；不发明配置键。
2. 仅在实验启用且模型配置合法时显示 secondary model 的状态与编辑入口。
3. 通过既有安全配置边界更新全局 TOML；不回显密钥、不覆盖无关配置、不因保存假定当前会话已切换。
4. 在真实 0.31 ACP 会话中验证它对当前会话和新会话的实际效果。无法验证即时生效时，UI 必须写明“新会话生效”或“需重连”。
5. Agent/Swarm 卡片仅在 runtime 事件提供实际 `primary/secondary` 信息时显示模型；缺字段保留 unknown。

**Go / No-Go：**

- **Go：** 实验状态、全局配置和真实会话效果一致，且没有把 secondary model 写成 `session/set_config_option`。
- **No-Go：** 无法安全识别实验开关、更新会损坏无关 TOML、或当前会话生效语义无法验证。

### G2a — 插件与自定义 Agent 可观察性（P1）

**目标：** 先让用户知道当前会话可能受哪些插件、Agent 与 Skill 影响，再讨论任何管理写操作。

**实施：**

1. 插件状态严格分为：

   - `installed_on_disk`：仅来自可安全读取的 managed metadata；
   - `enabled_in_config`：配置或 manifest 证据；
   - `loaded_in_current_session` / `pending_reload` / `unknown`：仅由当前会话动态命令、Agent 事件或稳定运行时信号证明。

2. Agent 发现页保留官方优先级：显式 agent file > 项目 > `extra_agent_dirs` > 用户 > Plugin > 内置。当前会话无法归因时显示 unknown，不以磁盘扫描冒充已加载。
3. 对项目级 `override: true`、`SYSTEM.md`、自定义工具限制显示高风险提示：这些内容能替换系统提示词或收紧/保留工具权限；默认不显示其正文。
4. 将 `available_commands_update` 与来源标签贯通 live/replay，未知命令/Agent 形状保持 generic fallback。
5. 文案明确 plugin 变更需要 reload 或新会话；当前会话不得误报已刷新。
6. 仅做只读发现。插件安装、移除、启用、禁用、市场浏览和 plugin MCP 开关，只有在存在稳定、隔离、可审计的 Desktop 管理契约时才另立项开放。

**验收：**

- 目录存在不会被误报为当前会话已加载。
- 系统提示词、Agent 正文和凭据不会默认显示或写入 Desktop 日志。
- 同名 Agent 的优先级和 override 风险能正确表达；未知来源保持 unknown/fallback。

### G2b — Provider 安全配置体验（P1，独立于 G2a）

**目标：** 改善 Provider 配置可理解性，而不把未实现的 ACP Provider 管理误做成网络控制台。

**实施：**

1. 在独立 `src/modules/providers/` 中展示 Provider、模型绑定与 capability 摘要；原始 `config.toml` 保留为高级/排障入口。
2. 凭据只显示“未配置 / 已配置 / 上次 ACP 认证失败”等非敏感状态；禁止回显、导出或写入日志。
3. 第一阶段只做本地结构校验和现有 `kimi acp` 就绪/认证状态展示，不从 Desktop 对第三方 Provider 发送探测请求。
4. 只有出现稳定且可测试的上游 API 时，才另立项做连接测试、添加/删除 Provider 或凭据工作流。

**验收：**

- 保存后 CLI 可重新解析配置；字段错误时保留编辑状态。
- UI 不读取、渲染或记录真实密钥。
- “Provider 已配置”与“当前会话可用”不混为一谈。

### G3 — 后台任务与 Cron 可观察性（P2）

**目标：** 让 Agent 已经发起的后台任务和 Cron 工具结果在 Desktop 中可理解、可回放；不假装拥有工具控制 API。

**实施：**

1. 将 Task/Cron 的已观察工具调用归一化为：会话 id、工具调用 id、任务/计划 id、快照、终态、输出路径或调度结果。
2. 将 `TaskOutput` 的非阻塞快照与**Agent 收到的后续完成通知**贯通 translator、wire types、live、replay、store、tool registry、Tasks/Conversation UI 和 generic fallback。
3. G5 前，Windows 通知只承诺当前持续连接会话实际收到的后续事件；切换会话后的后台保活、跨会话路由和可靠提醒归入 G5。
4. `/tasks` 仅在当前 ACP 会话确实宣传或现有路径能成功处理时显示；否则保留普通 prompt 与限制说明。
5. Cron 只展示 Agent 已返回的调度结果缓存；没有稳定 Desktop 控制 API 前，不提供 `TaskStop`、`CronList`、`CronCreate`、`CronDelete` 的直接控制按钮。
6. 未来若加“请求 Agent 停止任务”，必须明确其是一个可见 prompt/工具审批流程，而非直接终止；它是独立产品设计项。

**验收：**

- 已观察到的 Task/Cron 事件在 live/replay 的状态、标题、结果和 unknown fallback 一致。
- `TaskOutput` 不阻塞 UI，且当前持续连接会话收到完成事件时不会丢失最终结果。
- G5 前不对切换会话后的后台通知作可靠性承诺，也没有误导性的控制按钮。

### G4 — 独立的低风险会话增强（P1/P2）

**目标：** 不因多活跃会话架构而延后不依赖它的基础体验。

**实施顺序：**

1. `copy`：从已渲染的最后一条 AI 消息复制，作为纯 Desktop 功能，不依赖 CLI slash command。
2. `export-md`：只有现有持久化会话数据足以保真导出时才实现；否则先定义本地导出格式、附件边界与敏感信息处理。
3. `export-debug-zip`、`add-dir`、`undo`、`init`：各自先核实 ACP/CLI 契约和副作用，再独立立小计划。
4. `btw`、`experiments`、`feedback`：不纳入本轮对齐承诺，等待清晰的产品/协议入口。

**验收：**

- 每个小功能独立提交、独立测试，并说明数据范围和副作用。
- 无契约支持的功能没有 Desktop 伪入口。

### G5 — 多活跃会话与上游依赖能力（P2，独立设计项）

**目标：** 消除切换会话时的单流限制，而不是只增加第二条连接。

**实施：**

1. 先完成设计与压力验证：`Map<sessionId, ViewState>`、每会话连接归属、重连、缓存上限、事件路由、通知路由、应用退出策略。
2. 保持单窗口；多窗口与现有 single-instance 规则冲突，另行立项。
3. `fork-at-turn` 继续保持上游阻塞：当前 `fork_session` 明确返回不支持。仅在获得 `session/fork` 或等价稳定契约后再设计 UI。

**验收：**

- A 会话事件绝不写入 B 会话 UI。
- 切换、断线、退出、重启后的工作进程语义可测试且可观察。
- 未实现 fork 前，`/fork` 文案准确说明限制，不指向不存在的功能。

## 4. 验证与交付规则

| 变更类型 | 最低验证 |
| --- | --- |
| 本根目录文档 | UTF-8、无尾随空格、`git diff --no-index --check /dev/null <file>` |
| 仓库内文档 | `git diff --check` |
| React / hook | 相邻 Vitest、`npx biome lint <changed-files>`、`npm run build` |
| Rust | 相邻测试、`cargo fmt --manifest-path src-tauri/Cargo.toml -- --check`、`npm run rust:check`、`npm run rust:clippy`、`npm run rust:test` |
| 跨 Rust + IPC + hook + UI | 上述 Rust/React 门槛 + `npm test` + 目标文件的接口链路检查 |
| ACP 协议变更 | 上述跨层门槛 + 0.30/0.31 fixture + `npm run smoke:acp` + ACP-only 门禁 |
| 真实桌面能力 | 按 `source/kimi-code-desktop/docs/plans/2026-07-18-webview2-acceptance.md` 在真实 Tauri/WebView2 中验收 |
| 发布 | `npm run release:preflight`；需要 MSI 时再运行 `npm run release:msi` |

交付报告必须分开说明“代码已实现”“自动化测试已过”“真实桌面已验收”。本机认证、网络或 CLI 缺失导致的阻塞，不能报告为代码回归。

## 5. 完成定义

本计划作为文档的完成条件是：每项承诺都有已核实的协议来源、明确的上游依赖、正确的文件职责、可执行的验收标准、安全降级路径和热点文件所有权规则。

产品实施按 Gate 分别宣布完成。G5 未完成不妨碍 G0–G4 稳定交付；没有稳定上游控制契约的能力必须持续标为“观察/受限/未支持”，不能为了命令数量对齐而宣称完成。
